# Инвентаризация SharePoint - фаза 1

Дата среза: 6 сентября 2026 года.

## Цель и границы

Это метаданные доступного учебного архива MAXIMUM в SharePoint. Фаза не скачивает
весь архив и не меняет каталог приложения. Она отделяет уже импортированный
минимальный набор диагностик от источников для расширения банка.

Источник: `Разработка 2024-2025 / Shared Documents / КОНТЕНТ ЛК / Контент приложения`.

## Что фиксировать дальше

Следующая фаза проходит только папки `11 класс` и `9 класс`, затем формирует
машиночитаемый manifest со следующими полями:

`path`, `file_name`, `extension`, `size`, `modified_at`, `exam`, `subject`,
`grade`, `year`, `topic_hint`, `declared_question_count`, `has_answer_key`,
`has_explanation`, `has_images`, `content_hash`, `duplicate_group`, `ingestion_status`.

Размеры, хэши, ключи и дубли нельзя выводить из имени файла. Их нужно получать
после выборочной загрузки документов по тематическим пакетам. Сначала будут
выбраны документы с явным числом заданий в имени и отдельными исходниками,
затем конвертер выполнит dry-run без изменения `school/`.

## Результат фазы 2

Инструмент manifest, дедупликация и dry-run готовы и проверены на 20 DOCX
папки `Диагностики`; загрузка тематической выборки ждёт доступа к SharePoint.
Подробности в [PHASE_2.md](PHASE_2.md).

## Критерий отбора для следующего расширения

Для каждого предмета нужны несколько тем, несколько типов заданий, ключи,
объяснения и доступные изображения. Документ считается кандидатом только после
строгой проверки формата и редакционной проверки. Нельзя расширять runtime-каталог
простым копированием всех найденных DOCX.
