# ТЗ на закрытие замечаний UI/UX-аудита Mini App «MAXIMUM Diagnostics»

Версия 1.1 · 7 сентября 2026 · Основание: отчёт «UI/UX-аудит Mini App» (58 замечаний F-01…F-58), Linear KIR-218. В версии 1.1 зафиксированы продуктовые решения: пропуск задания вводится, экран прогноза возвращается, таймер не вводится, перевыгрузка контента выполняется разработчиком без методиста.

## 0. Как читать документ

Документ закрывает все 58 замечаний аудита. Работа разбита на 15 рабочих пакетов (РП), сгруппированных в четыре фазы. Каждый пакет — один PR (или два тесно связанных), у него есть: цель, что именно меняем (поведение, UI, данные, бэкенд), список файлов, критерии приёмки, тесты и какие замечания он закрывает. В конце — сквозные разделы: изменения формата контента, план проверки, порядок выкладки, оценка.

Оценки в человеко-днях разработчика (фронтенд, если не сказано иное), без дизайна. Приёмка формулируется так, чтобы её мог проверить скрипт прогона `walk.py` из папки аудита или человек по перечисленным заданиям каталога.

Обозначения: `Q(набор, номер)` — задание в прогоне аудита, например `Q(ege-chemistry, 05)` = пятое задание полной диагностики ЕГЭ по химии. Файлы указаны относительно корня репозитория.

## 1. Принципы, общие для всех пакетов

1. **Формат экзамена — источник истины.** Обозначения вариантов, порядок столбцов, форма ответа (последовательность цифр под буквами) повторяют бланк ОГЭ/ЕГЭ. Латинские маркеры A–E не генерируются нигде.
2. **Тип ответа приходит из контента, а не угадывается регулярками по условию.** Поле `answer_format` (см. раздел 17) заменяет `answerInputConfig` и эвристики `DIGIT_ANSWER`.
3. **Ничего не теряется молча.** Любое неактивное состояние (кнопка, строка, вариант) объясняет причину текстом рядом.
4. **Одна сущность — одно название.** «План» (не маршрут/прогноз), «Задания на сегодня», обращение на «ты» во всех UI-строках; текст самих заданий не редактируется.
5. **Каждый пакет проверяется на реальном каталоге**, а не на фикстурах галереи. В `design-preview.gallery.test.tsx` добавляются фикстуры из реальных заданий (см. раздел 18).
6. **Правки контента идут через импортёр и валидатор**, не руками в `sp-*` вопросах (правило репозитория).

## РП-01. Активация «Следующее задание» и объяснение блокировки

Закрывает: F-01, F-26, F-32. Приоритет P0. Оценка: 1,5 д фронт (часть a — 0,5 д, часть b — 0,5 д, часть c — 0,5 д) + 0,5 д бэкенд.

### Цель
Любой валидный ответ любого типа активирует переход. Неактивная кнопка всегда объясняет, чего не хватает. Кнопка видна на любом скролле.

### Поведение
`isAnswered(question, answer)` в `miniapp/app/question-screen.tsx` переписать как исчерпывающий `switch` по типу и по `answer_format`:

| Тип / формат | Условие «отвечено» | Текст причины при неполном ответе |
|---|---|---|
| single | выбран один вариант | «Выбери вариант» |
| multiple, лимит известен | выбрано ровно `selection_limit` | «Выбрано 1 из 2» |
| multiple, лимит неизвестен | выбран хотя бы один | «Выбери все подходящие варианты» |
| matching (все виды) | все позиции заполнены и нет запрещённых повторов | «Осталось заполнить: Б, В» / «Вариант 3 выбран дважды» |
| input · number | `isValidNumericInput` | «Введи число» |
| input · sequence:N | ровно N допустимых цифр, повторы по `allow_reuse` | «Заполнено 2 из 3» |
| text · word / words | `isValidTextInput(answer, max_length)` | «Введи ответ» |

До появления `answer_format` в контенте (РП-10) для `text` использовать `isValidTextInput`, для `input` — текущую логику. Это часть **a**, она выкладывается первой и отдельно.

### UI
- Под кнопкой строка `role="status"` с текстом причины (14px, `--muted`, не `--faint`). Появляется только при `disabled`.
- **Часть b (липкий бар):** обёртка кнопки `position: sticky; bottom: 0; padding-bottom: calc(12px + env(safe-area-inset-bottom))`, фон `--paper`, тень `0 -8px 24px rgba(0,0,0,.06)`. Строка «Прогресс сохраняется автоматически» переезжает в шапку (см. РП-08) и показывается один раз за сессию как тост.
- Disabled-состояние: текст `--muted` на `--surface-2`, пунктирная рамка `1.5px dashed var(--control-line)` (токен из РП-15).
- **Часть c — пропуск задания (решение принято 07.09.2026: вводим).** Вторичная кнопка «Не знаю, дальше» под основной. Тап сохраняет для текущего задания значение-маркер пропуска и переходит дальше; на последнем задании — «Не знаю, получить результат». Пропущенное задание помечается в прогресс-рейле (пустой контур) и в сетке результата (серым, «пропущено»); вернуться и ответить можно через «←» до отправки. Подтверждение не нужно: действие обратимо до завершения.
  - Контракт: значение ответа для пропуска — пустая строка для input/text/single, пустой массив для multiple, пустой объект для matching. `POST /session/progress` эти формы уже принимает; проверить, что `saveLocalSession` и `updateNumericInputAnswer`/`updateTextInputAnswer` не вычищают пустые значения.
  - Бэкенд: `POST /session/complete` сейчас требует `set(body.answers) == expected_ids`, поэтому пропуск обязан присутствовать в `answers` с пустым значением. `scoring.is_answer_correct` возвращает false для пустого значения (проверить для всех пяти типов, добавить тесты); в `ServerResult` добавить `skipped_count`, в `per_question` (РП-11) статус `skipped`. Разбор показывает «Ты пропустил задание» вместо «Ты ответил: —». В PDF-отчёте (`report.py`) пропуск — отдельная строка «пропущено N». Аналитика: событие `question_skipped` в funnel.
  - Тренажёр: пропуск не вводится (там нужен ответ для фидбэка).

### Тесты

## РП-10. Контент: импорт, валидация, перевыгрузка, формат ответа

Закрывает: F-04, F-05, F-17, F-45, часть F-14, F-16, F-18. P0. 2,5 д бэкенд/скрипты. Методист не требуется (решение 07.09.2026), см. подраздел «Без методиста».

### Валидатор `scripts/validate_school.py` (новые проверки, все — ошибки, не предупреждения)
- Плейсхолдеры `___` в `prompt`, если в задании есть маркеры позиций или фраза «соответствующую буквам».
- Число позиций (буквы) и число вариантов: вариантов не меньше позиций, если `allow_reuse=false`.
- Смешанные алфавиты внутри одного токена; кириллические токены, совпадающие с символами элементов, внутри формул.
- Формулы с известными пропущенными индексами (список: BaCl, FeCl, AlCl, CaCl, MgCl, NaS, KS без цифр).
- Дубли вариантов в одном задании (`Кислота` ×2).
- Стем, заканчивающийся на ` .`, ` :` или пустой после удаления формулы.
- `answer_format` обязателен для `input` и `text`; `answer_length` обязателен для `sequence`.
- `|` в тексте `prompt` вне структурного блока таблицы запрещён.

### Без методиста: что автоматизируется, а что нет
Исходные DOCX лежат локально в `.tmp/sharepoint-sample/` (56 + 20 файлов, структура SharePoint), импорт полностью локальный: `python scripts/import_sharepoint_diagnostics.py .tmp/sharepoint-sample`, скрипт идемпотентен. Проверка источников показала:

- `Q(ege-chemistry, 05)`: в DOCX все девять вариантов лежат в ячейках таблицы, импортёр склеил их через « | ». Дефект импортёра, чинится правилом 1 и перезапуском импорта. Так же устроены все «| »-таблицы во всех предметах (правило 2).
- `Q(ege-chemistry, 14)`: в DOCX условия позиций А и Б отсутствуют физически (ни текста, ни OMML-формул, ни картинок), «___» — это пустые ячейки таблицы. Восстановить автоматически нельзя. Правило: валидатор помечает такие задания (`missing_position`), импортёр исключает их из каталога с записью в report.md (как уже делается для `missing_figure`, `irregular_key`). Диагностика ЕГЭ-химии становится на 1–2 задания короче, и это лучше нерешаемого задания. Так же поступить с `Q(ege-chemistry, 17)` и `Q(ege-biology, 18)`. Восстановить эти задания сможет любой, у кого есть исходный вариант КИМ; задача уходит в бэклог и не блокирует.
- `Q(oge-math, 06, 08, 09, 13)`: формулы в DOCX даны картинками, текстовая разметка невозможна без ручного набора. Без методиста: не апскейлить и давать зум (РП-09), а стем с висящей точкой чинить правилом импортёра («Найдите значение выражения .» → «Найдите значение выражения:» + картинка). Перенабор формул в текст — отдельная задача на будущее.
- `answer_format` и `answer_length` выводятся автоматически: по типу задания (single/multiple/matching не нуждаются), по ключевым фразам условия («последовательность цифр, соответствующую буквам АБВГ» → sequence, длина = число букв; «запишите слово/словосочетание» → word/words; «выпишите … два слова» → words; остальное для input → number) и по длине ключа в поле `correct` (для sequence длина ключа обязана равняться `answer_length`, расхождение — ошибка валидатора). Ключи есть в DOCX, поэтому проверка полная, а не эвристическая.
- `allow_reuse` — по фразе «цифры в ответе могут повторяться» или если вариантов меньше позиций.
- `max_primary_score` — по таблице спецификации ФИПИ 2026 «номер задания → первичный балл» для каждого экзамена и предмета (заносится один раз в `docs/SCORE_SCALES_2026.md`, где уже есть шкалы перевода); номер задания КИМ берётся из `source.exam_position` (заголовки «Задание N» в DOCX). `approval_status: approved` проставляется автоматически всем заданиям, прошедшим строгий валидатор.
- Кириллица в символах элементов, регистр CL, пробелы после точек, артефакты бланка — детерминированные правила импортёра, покрываются тестами на реальных строках. Замечание: «___» встречается в каталоге 262 раза, большинство — легитимные пропуски в текстах (английский, словообразование); валидатор флагует только плейсхолдеры на месте позиций сопоставления.

Итог: перевыгрузка = правки импортёра и валидатора + перезапуск импорта + просмотр report.md разработчиком. Ручной труд остаётся для трёх заданий с отсутствующими позициями и для перенабора формул математики; обе задачи не блокируют релиз.

4. Для каждого input/text задания проставлен `answer_format`; для sequence длина совпадает с длиной ключа (тест по всему каталогу).
3. Python-тесты каталога зелёные; `tests/test_import_*` покрывают правила 1–5 фикстурами из реальных строк.
